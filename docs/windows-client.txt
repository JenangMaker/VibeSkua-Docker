VibeSkua for Windows (test build)
================================

VibeSkua's Avalonia client with each tab's game in Ruffle's desktop player:
no Flash Player and no browser. Built from the "windows" branch.

Running it
----------
1. Extract the zip anywhere (keep the folder together: skua.swf and the
   ruffle folder must stay next to the .exe files).
2. Run VibeSkua.exe, or VibeSkua Manager.exe (below). Windows may warn that
   the app is unsigned (SmartScreen): "More info" > "Run anyway".
3. Log in by hand in the game window, start accounts from the Manager, or set
   them in the environment (see below).

VibeSkua Manager
----------------
Like Skua Manager: keep your accounts (with tags and groups), pick a login
server and a script, and start them. Each started account opens as a tab of
VibeSkua (started first if it is not running), logs in, and loads the script
(starting it with Auto-start). Starting an account again reuses its tab.
- Accounts: add, tag, group, start one, the selected ones, a group, or all.
- Running: VibeSkua's tabs; show, restart or close one.
- Scripts: update or reset the scripts. Themes, About.
Not in this Manager: Skua Manager's Updater and Options tabs, and Goals.
Accounts it starts are also saved in VibeSkua's accounts file
(%AppData%\vibeskua\accounts.json), so they open again when VibeSkua starts.

What to expect
--------------
- Each tab's game sits inside its tab, under Skua's menu, as in the Docker
  desktop; tabs that are not shown keep running, slowed down.
- The first start downloads the scripts (about 1900) to
  %AppData%\Skua\Scripts, as Skua does.
- The first script start asks the Data Collection question once, and
  CoreBots may restart the first script once while it builds its quest cache.
- A script with options opens its Options window and waits for Start.
  SKUA_SKIP_SCRIPT_OPTIONS=1 starts with the saved options instead.
- Closing VibeSkua's window ends every tab and its game.
- The original Skua.Manager cannot launch this client; use VibeSkua Manager.

Settings (environment variables, all optional)
----------------------------------------------
SKUA_TABS                  number of tabs (0: a single Skua, no tab strip)
AQW_USER_1, AQW_PASS_1     tab 1's account (_2 for tab 2, ...); logs it in
AQW_SERVER_1               tab 1's server
SKUA_SCRIPT_1              script for tab 1 (full path), started after login
                           with SKUA_SCRIPT_AUTO_START_1=1
SKUA_SKIP_SCRIPT_OPTIONS   1: do not open a script's Options window
RUFFLE_QUALITY             low (default), medium, high: anti-aliasing; also
                           the most the game can raise it to
RUFFLE_MAX_QUALITY         that limit on its own (default: RUFFLE_QUALITY)
RUFFLE_GRAPHICS            the player's graphics API (default: its own choice)
RUFFLE_FILTERS             on (default here): glows, blurs and blend effects;
                           off draws faster, as the Docker build does
RUFFLE_IDLE_PICK_MS        how often the player checks what is under a resting
                           mouse, in ms (default 100; 0: after every update,
                           which halves the frame rate with the pointer over
                           the game)
RUFFLE_GPU_MEMORY          low (default): the player takes GPU memory in small
                           blocks (about 130 MB a player at login instead
                           of 290 MB); performance: wgpu's own large blocks

The control API listens on 127.0.0.1 only: 8791 for tab 1, 8801 for tab 2...
(GET /status). The same settings as the Docker image apply; see DOCKER.md in
the repository.
